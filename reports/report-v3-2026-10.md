| Параметр | Значение |

| Сообщение коммита | `feat: add new-csv-to-markdown__v3.mjs generator with burial fields, tags and warunit placeholder` |

### Что сделано
1. **Новый генератор** Markdown-карточек из CSV на базе `new-csv-to-markdown-v2.mjs`. Файлы v1/v2 не изменялись.
2. **Блок захоронений** переработан:
   - `**Первичное место захоронения (по данным портала obd-memorial)**` ← `primary_burial`;
   - `**Захоронен**` ← `current_burial` (фактическое; если пусто — строка не выводится);
   - `**Страна и регион захоронения** Россия, Крым` — **жёстко**, строка появляется только при наличии данных о захоронении;
   - `**Откуда перезахоронен**` ← `rebural_from`.
3. **`normalizeWarUnit()`** — заглушка с комментарием `ТУТ ВСТАВЬТЕ ЭТО` для будущей расшифровки шифрограмм войсковых частей («398 сд 821 сп» → полное наименование + краткий обзор боевого пути). Механизм: словарь `data/dictionaries/units_dict.json` или аналог.
4. **Теги во frontmatter** — поле `tags:` (YAML-список, формат автора шаблона Retypeset) из `warunit`, `primary_burial`, `current_burial`, с комментарием `ТУТ ЗАПОЛНИТЕ ТЕГИ`. Назначение: секция «сослуживцы» в Астро-сборке (клик по тегу формирует представление всех карточек) + отдельная RSS-лента для Дзена.
5. **`published`** — обязательное поле схемы (`z.date()`): берётся из колонки «Дата» CSV, иначе — текущая дата (ISO `YYYY-MM-DD`). Без него RSS `pubDate` невалиден.
6. Сохранено из v2:
   - чтение всех `*.csv` из `data/csv/` (включая вложенные каталоги);
   - `slug = bitva-za-krym-1942-<document_id>` (без транслитерации ФИО);
   - логирование: `scripts/logs/run.log`, `refused.log`, `errors.json`;
   - режим `--dry-run` (ничего не пишет);
   - правило «поле выводится только если непустое»;
   - `cause_of_death` — НЕ выводится (осознанно пропущен).

### Проверка
- ✅ Файл добавлен и закоммичен.
- ⚠️ Не запускался (по правилам сессии локально не исполняется). Проверка через `--dry-run` — на стороне пользователя.

## 2. Файл: `obd-edge_v03.js`

| Параметр | Значение |
|---|---|
| Репозиторий | `ermek-toptaev-1/puppeteer-project` |
| Ветка | `main` |
| Путь | `obd-edge_v03.js` (новый, в корне, рядом с `obd-edge.js`) |
| Коммит | `25583cf139b7830b1a3badf89f2676ea4f04e372` |
| Сообщение коммита | `feat: add obd-edge_v03.js parser with country_burial, region_burial, rebural_from columns` |

### Что сделано
1. **Новый парсер** карточек OBD Memorial на основе текущего `obd-edge.js`. Исходный файл не изменялся.
2. **Новые колонки CSV** добавлены в `headers` (после `current_burial`):
   - `country_burial` ← `Страна захоронения`;
   - `region_burial` ← `Регион захоронения`;
   - `rebural_from` ← `Откуда перезахоронен`.
   Заполняются **только если есть в карточке**.
3. **`current_burial` без fallback** на «Первичное место захоронения» — берётся только «Место захоронения». Конфликта нет: первичное и фактическое хранятся раздельно (мы делаем копию документа ЦАМО, ничего не придумываем).
4. **`knownTitles`** дополнен тремя новыми полями — они не утекают в `notes`.
5. **Логика `notes` — «тормоз»**: карточка без проверки не появляется. В `notes` попадают только проблемные/нестандартные данные:
   - причина, если не «убит/погиб»;
   - неизвестные поля, если архивные реквизиты (`nomer_fonda`, `nomer_opisi`, `nomer_dela`, `document_type`) пусты.
6. Сохранено из исходного `obd-edge.js`:
   - подключение к Edge по CDP (`--port`, по умолчанию 9226);
   - контроль дублей внутри файла и по глобальной сумме;
   - журналы `processed.txt` + `data/summary/processed_ids.txt`;
   - промежуточное сохранение каждые 50 записей;
   - `--dry-run`;
   - классификация «убит/погиб».

### Проверка
- ✅ Файл добавлен и закоммичен.

## 3. Согласованность связки

- `obd-edge_v03.js` выдаёт CSV с колонками `country_burial`, `region_burial`, `rebural_from`;
- `new-csv-to-markdown__v3.mjs` читает эти колонки и выводит в карточку:
  - страна и регион — жёстко «Россия, Крым» (проект узкий);
  - первичное место захоронения — с подписью «по данным портала obd-memorial»;
  - фактическое место — как указано, если есть;
  - перезахоронение — как указано, если есть;
- теги из `warunit` / `primary_burial` / `current_burial` → frontmatter `tags` → секция «сослуживцы» + отдельная RSS-лента для Дзена.
