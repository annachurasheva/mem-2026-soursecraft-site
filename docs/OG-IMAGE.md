## Как устроен URL `/og/bratskaya-mogila-frontovoe.png`

Этот URL **уже формируется автоматически** и ничего размещать вручную не нужно. Работает так:

1. `src/pages/og/[...image].ts` (плагин `astro-og-canvas`) при каждой сборке берёт **ваши посты** (`src/content/posts/*.md`) и для каждого генерирует PNG по адресу `/og/{id-поста}.png`.
2. Картинка рисуется на лету: заголовок и описание **из вашего поста** + логотип + фон. Это не «чужая» картинка — это ваши данные, отрисованные канвасом.
3. `Head.astro` вставляет этот URL в `<meta property="og:image">` и в JSON-LD `image`.

То есть для постов функция **уже ваша**: `https://mem-2026.sourcecraft.site/og/bratskaya-mogila-frontovoe.png` появится после деплоя, и это будет картинка с текстом вашего поста.

## Что в этой схеме «чужое» — два места

**1. Логотип в углу OG-картинки** — `public/icons/og-logo.png`.
Это единственный графический файл, который сейчас рисуется на всех сгенерированных картинках (логотип шаблона Retypeset). Чтобы сделать своим — просто **замените этот файл** на свой (PNG, можно прозрачный). Путь менять не обязательно.

**2. Fallback для не-постовых страниц** — вот тут реально «чужой сервис».
В `Head.astro` для страниц *без* `postSlug` (главная, `/about`, `/tags`, `/privacy`) при пустом `apiflashKey` подставляется:

Это скриншот **чужого сайта** (демо-шаблона). Именно это вы и почувствовали как «чужое».

## Что можно сделать (варианты)

| Вариант | Что делаем |
|---|---|
| **A.** Оставить генерацию канвасом | Ничего не размещаете; заменить только `public/icons/og-logo.png` на свой логотип |
| **B.** Своя фотография для поста | Доработать: добавить поле `ogImage`/`cover` в схему поста и в `Head.astro` — если задано, использовать вашу картинку из `public/`, иначе канвас |
| **C.** Разобраться с не-постовыми страницами | Либо получить свой ключ на apiflash.com и вписать в `apiflashKey`, либо задать свои статические OG (например, `public/og/index.png`) и убрать чужой fallback |
